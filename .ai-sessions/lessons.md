# Lessons Learned

## Recent

- A validator loop that trips its cap on every batch is usually rationing findings, and the fix is in the dispatch contract, not a bigger cap: in 0.7.3 the cold validator reported 1 or 2 findings per pass on batch `sweep` and 7 when told to report everything, and each fix added new contract surface that nobody re-read. Tell the validator to report every finding in one pass, give re-check passes `Previous findings:` and a `Fix delta:` of two tree ids, and let the cap extend only while the `block` plus `warn` count drops. Dogfooded on its own diff, that went 3 warn then 2 warn, both new findings on lines the fix touched, and the re-check cost 86k tokens and 46 seconds against 110k and 96 for the cold pass. (2026-11-13)
- `git diff HEAD --name-only` leaves out untracked files, so a mechanical check built on it (the `paths:` and `deps: frozen` spec fences) passes a brand-new file unseen; add the untracked paths from `git status --short` everywhere the check is stated. (2026-11-13)

## Workflow

- Before recommending or running `/bpe:retrofit --resync` on a repo mid-release, check whether spec.md's dated work packages are shipped or active: the Structure Migration treats every dated section as phase content to archive, and would have moved the 0.7.2 package that `/bpe:plan` was about to read. Sequence resync after the release line ships, or keep active packages under `**Upcoming:**` explicitly. (2026-11-09)

- Before triaging open issues, grep the tree for each issue's claim: two of thirteen were already resolved (#24 fixed in 0.6.3 by a PR with no `Closes`, #36's `--from <path>` ask already met by apply-review's argument) and one doc claim was false (`plan/SKILL.md` says the executor consults MCPs; it had no MCP access). - Before shipping a branch that includes a large rewrite, sweep for content regressions with greppable tokens from each historical fix's commit subject (4000-char cap, SEQUENTIAL, promotion trail). Being 0 commits behind main proves nothing about content: a migration step can rewrite a file wholesale and drop a fix while git history stays clean. (2026-07-15)
- Meta-projects (BPE improving BPE, or any tool improving itself) hit a bootstrap paradox: templates that don't exist yet can't be used to plan the work that creates them. Default answer: hand-write plan.md for the meta-project and note the bootstrap explicitly in spec.md's "Plan generation approach" section. Regenerating with the new command after the template lands is optional but rarely worth the churn mid-flight. (2026-07-04)
- When edits happen outside the user's CWD (e.g. a sibling repo), state the absolute path of the parent repo on every file change, not just once. (2026-05-24)
- Don't bulk-apply a user-articulated rule before confirming target scope; misrouted prompts and ambiguous "the skill" references are common. (2026-05-24)
- Bucket subagent audit findings into 3-4 user-facing decision groups for one multi-select AskUserQuestion rather than flat per-item questions. (2026-05-24)
- Before bumping a plugin version, check the live committed version with `git show HEAD:<manifest>`; one uncommitted working set bumps once, not per-file. (2026-05-24)
- When testing undocumented features via subagents, have the subagent write evidence to a file you can Read back; don't trust the spoken summary alone. (2026-05-24)
- For any "drift" or "is this in sync" question, run `stat -c "%y %s %n"` + `diff -q` on every pair of paths up front before discussing what should win. Direction-of-drift can vary file-by-file in the same tree (one file repo-newer, another live-newer). Cheap, comprehensive, prevents data-loss mistakes from acting on partial information. (2026-06-10)
- When a step changes a document's core contract (e.g. adding a second template beside the TDD one), end the implement pass with a grep for the old contract's key phrases ("TDD", "RED-GREEN") and read every hit: frontmatter descriptions, intro sentences, and numbered requirements keep asserting the old single-contract world. All three warn findings so far in the 0.6.0 goal run (A2 README structure, B1 description + Requirement 6, B1 intro clause) were this class of stale-claim miss, costing two fix round trips in B1 alone. (2026-07-05)
- Contract-changing edits (adding a second template, renaming a format, widening a scheme) leave stale single-contract claims behind in the same file: frontmatter descriptions, intro sentences, numbered requirements. End the edit with a grep for the old contract's key phrases and read every hit before handing off for review. (2026-07-05)
- A large in-flight rewrite can silently revert a recent point fix to the same file: the fable rewrite of review/SKILL.md dropped the week-old `mktemp -u` fix. After a rewrite pass lands on a file with a recent targeted fix, grep for the fix's key token before assuming it survived. (2026-07-15)
- When parking designed-but-unstarted work, write a dated plan file (e.g. `vX.Y-plan.md`) at the repo root capturing decisions, rationale, the per-file change set, and an explicit resume entry point (what to read first, where to start, branch reminder). A cold session then resumes without replaying the design conversation. (2026-08-08)
- Before choosing a home for generated data, compare its lifetime to the file's: plan.md is archived every phase, so an out-of-scope list there would be regenerated and re-confirmed each phase and its second life (the backlog of likely future work) thrown away. Data that must outlive a phase belongs in the permanent layer (spec.md) even when it is produced per phase; the never/later/now sort (Non-goals / Deferred / Goals) fell out of that check, and it reversed a decision locked the day before across three files. (2026-09-14)

## Git

- Never chain a destructive git step after a step whose failure is not checked: `gh pr merge ... ; git checkout main ; git pull ; git branch -D <branch>` deleted the local branch after the merge had refused on conflicts (main had moved). Recoverable only because the remote branch survived. Gate every step on the previous one (`&&` or `set -e`), and put the branch deletion last, after the merge is verified. Also: preview conflicts with `git merge-tree --write-tree --name-only <base> <branch>` before merging; it names the conflicting files without touching the tree. (2026-09-19)

## Infrastructure

- Dotfile deploys via `copy` accumulate drift silently. Every live-side edit (manual or via tooling like Claude Code) creates divergence the next deploy can silently overwrite. For "repo as source of truth" paths, deploy via symlink; live edits surface as `git status` changes in the repo, and drift is structurally impossible. Per-machine runtime state (history.jsonl, credentials, caches) should still be local; only symlink the tracked dotfiles. (2026-06-10)

## Tooling

(2026-11-09)

- Auto mode's classifier can return "no verdict" on an Edit, which the harness treats as a hard refusal that a retry does not change; it refused every Edit to `bpe/references/*.md` and `bpe/agents/*.md` in this session, with a `/goal` active and after `/goal clear`. - `chrome-headless-shell --virtual-time-budget=Nms` deterministically advances JS timers during a screenshot; use it to capture transient UI states and async-rendered content. (2026-05-24)
- For Python f-strings embedding JS object literals, double every JS brace `{{ }}` to escape. (2026-05-24)
- Ansible `--check` mode skips `ansible.builtin.shell` tasks, making any migration playbook that uses shell-based pre-work (backup-then-link, mv-aside-then-symlink) look broken in dry-run. Take a manual snapshot of target paths and run for real; don't trust `--check --diff` for these flows. (2026-06-10)
- `ansible.builtin.file state=link force=true` cannot replace a non-empty directory with a symlink; module refuses with "directory is not empty". For migrations from a real-dir layout to symlinked layout, run an explicit `ansible.builtin.shell` `mv` step first to move the existing directory aside, then create the symlink. `force: true` works for files, not for non-empty directories. (2026-06-10)
- An SSH signing agent socket can die across a long session gap (a remote-control session that spans days) and come back on the next resume: `git rebase` failed with "Couldn't get agent socket" and the same command succeeded a session later with no config change. Before concluding signing is broken, run `ssh-add -l` and check `SSH_AUTH_SOCK`; if the key is listed, retry. `git rebase --abort` restores the branch cleanly when a re-sign fails mid-replay, and `--no-gpg-sign` is never the fix. (2026-09-14)
- A baseline with zero instances of a code path cannot verify that path: the 0.7.2 transcript has no SendMessage continuations, so matching its Verify numbers proved nothing about how `goal-run-report.py` classifies them, and the validator found three bugs there. Build a small synthetic fixture for any path the baseline lacks before relying on the script for the comparison run. (2026-11-11)

- The orchestrator cannot see its own context size, but the session transcript JSONL records per-assistant-turn usage (`input_tokens` + `cache_read_input_tokens` + `cache_creation_input_tokens` is the live context). - Before renumbering a skill's numbered procedure, grep the agent files that follow it inline for literal step numbers: `agents/step-executor.md` mapped execute-plan's "ask the user" points as "steps 6 and 10", and inserting a step 8 would have silently pointed it at the wrong steps. Agents that execute a SKILL.md inline carry a hidden cross-reference to its numbering. (2026-09-18)
- A public plugin that reads the user's config must describe a discovery rule, never one user's filenames: brainstorm's vendoring sources were written as "skills plus `~/.claude/rules/`" (Mason's layout), which coupled BPE's timeline to his private writing refactor and would have missed any other user's layout. Restated as "session skills, `~/.claude/rules/*.md`, and files `~/.claude/CLAUDE.md` imports with `@path`", it picked up the refactor's new `@writing-hard-rules.md` the day it landed with no BPE change. When two repos are converging, write the shared contract as a rule in the public one and let the private one meet it. (2026-09-18)
- When a design hinges on whether Claude Code supports something (a per-user override, a loading rule), check the docs before proposing a workaround: `claudeMdExcludes` in the gitignored `.claude/settings.local.json` skips project rules files per user (globs against absolute paths, arrays merge across layers), which turned "accept duplicated rules in the author's context" into "the author loads only the source". Dispatch `claude-code-guide` or WebFetch code.claude.com/docs; a limitation that does not exist was one sentence away from shaping the design. (2026-09-14)
- Family aliases in frontmatter (`opus`, `sonnet`, `haiku`) make model-generation upgrades automatic, so the drift hides in documentation examples instead: after a new generation ships, grep for dated model IDs (`claude-[a-z]*-[0-9]`) across the repo, because example blocks teach the stale pattern even when nothing functional pins it. Grep is a stopgap: the hand-synced `.claude/bpe.local.md.example` copy of the tier map drifted again while the map itself stayed current (it cited an old date and pinned a stale `claude-fable-5` ID, with seats that contradicted the very map it claimed to mirror), and only the validator caught it. The durable fix for the class is one machine-readable source: the YAML tier-map block that `/bpe:init` (0.7.4, #28) reads to generate the example, so there is no second copy left to hand-sync. (2026-11-09)
- Claude Code loads the skill registry at session start, so editing `disable-model-invocation` (or any SKILL.md frontmatter) has no effect until the session reloads; the Skill tool keeps refusing under the old policy for the rest of the session. Plan flag flips to land at a session boundary and expect to finish the current one under the old behavior. Separately, that flag gates only the main loop: subagents cannot invoke slash commands at all, so `bpe:step-executor` must read the SKILL.md and execute its procedure inline no matter what the flag says. Unblocking a skill therefore creates two paths to the same procedure rather than replacing one. (2026-07-28)
- Punctuation that is cosmetic in body prose is load-bearing in skill frontmatter: replacing an em-dash with `: ` inside an unquoted YAML `description:` scalar makes the block unparseable ("mapping values are not allowed here"), which silently breaks the skill's description. After editing any frontmatter field, parse every SKILL.md frontmatter block as YAML before shipping. Related: make bulk text rewrites assertion-guarded and all-or-nothing (anchor each replacement to its exact line, abort the whole run on any miss), which caught three wrong patterns here before a single file was written. (2026-07-27)
- Before trimming emphasis (CRITICAL/MANDATORY tags, bold-caps requirement blocks) from a skill, check its `model:` frontmatter: a skill pinned to a weaker tier may keep firmer language deliberately, per the Claude 5 guidance that judgment-based prompting is a frontier-model property. Redundant restatement of the same rule is still deletable at any tier; only the firmness of the single remaining statement is tier-dependent. (2026-07-25)
- Prompt-based Claude Code hooks get ONLY the hook-input JSON (prompt text via `$USER_PROMPT` substitution); they cannot read files, see process env vars, or know the session model, and a `.md` file cannot be registered as a hook (configs are JSON, pointed at by plugin.json's `hooks` field). When a hook's decision needs file/env/model state, have the hook do detection only and inject `additionalContext` delegating the resolution to the session agent, which can observe all three. (2026-07-15)
- When a feedback channel's consumer ignores a field by design (apply-review never reads a comment on `ship`), block collecting the field in the UI rather than teaching the consumer to read it; disable and clear the input at decision time so the contradiction can't be saved. Keep a surfacing guard in the consumer for legacy payloads. (2026-07-15)
- Claude Code skills support `model:` in SKILL.md frontmatter (per-turn override, not per-invocation) and `disable-model-invocation: true` to block auto-triggering. The `opus`/`sonnet`/`haiku` aliases resolve to the latest model available in each family, which handles context-specific model availability (work-vs-personal Fable access) without custom capability tokens. Migration path: commands and skills are unified under `/name`; a command file and a SKILL.md at the equivalent path both create `/name` and are interchangeable. Migrate BPE commands to skills to unlock tier enforcement. (2026-07-04)
- Never give a prompt-based hook a branch where the common case must answer a bare `{}` sentinel; judge narration gets surfaced as a BLOCK. Mechanical branch decisions (prefix regex) belong in `type: command` hooks that exit 0 silently on pass-through. (2026-07-16)
- For consistent skill/command output, lift invariants (CSS, schema, structure) into version-controlled assets; let the LLM fill in content, not invent layout. (2026-05-24)
- Inline `<style>` injection from the server keeps a served HTML page self-contained without forcing the LLM to inline CSS or maintain a separate static route. (2026-05-24)
- A two-level TOC (group divider + nested units) should be pinned as a hard rule in the contract; CSS rarely styles deeper, and the gap isn't visible until needed. (2026-05-24)
- Plugin subagents inherit auto-mode from the parent; `permissionMode` is ignored in plugin agent frontmatter. Put the parent session in auto mode via the client's mechanism (TUI: keyboard shortcut, NOT a slash command; `/auto` does not exist). Classifier auto-pauses after 3 consecutive or 20 total blocks. (2026-05-24, corrected 2026-05-30)
- `/goal`'s condition is capped at 4000 chars. Autonomous-mode wrappers must split orchestrator instructions (normal message) from `/goal <condition>` (separate slash invocation); packaging them inline blows the cap. The goal.md playbook lives inside `goal/SKILL.md` and is written verbatim into that `/goal` argument, so any step that edits the playbook must re-render it with real values and measure the result: a first draft of the finalize-red step landed at 4026 chars and would have silently broken every future `/bpe:goal` invocation. (2026-11-09)
- Verify slash commands exist locally before baking them into user-facing emitted strings; single-source research output can fabricate. Cross-check against the skills list or `/help`. (2026-05-30)
- Subagents can invoke the `Skill` tool at runtime (undocumented but empirically verified). Use fully-qualified `plugin:name` form. Skill body arrives as injected human-role message. (2026-05-24)
- The `/goal` evaluator sees only the parent transcript; subagent tool calls are invisible. Subagent reports must surface every verification fact (test output, git status, commit SHA) in user-facing text. (2026-05-24)
- `/goal` is cleared by `/clear`; auto-compaction with `/goal` is undocumented. Sub-agent-per-step architecture sidesteps both: fresh context per dispatch, parent stays tiny, compaction never triggers. (2026-05-24)
- Triggering rules for skills (auto-fire, be "pushy") do not apply to slash commands (user-typed, slash menu) or plugin agents (explicit dispatch). Commands and agents need clarity and disambiguation, not push. (2026-05-24)
- Inside an autonomous `/goal` loop or any subagent dispatch, slash commands cannot be invoked; there is no user-input channel. Procedures must say "Read the command file and execute its procedure inline," not "follow /bpe:X." Otherwise the model attempts the slash invocation, it silently fails, and the loop exits. (2026-05-29)
- Default to enumerated stage lists (`(a)` code, `(b)` `todo.md`, `(c)` session summary, `(d)` lessons.md if appended) in any autonomous-mode `git add` step. "Files this step touched" is ambiguous and the missing file silently fails the commit under pre-commit hook enforcement. (2026-05-30)
- Keep the autonomous-mode commit ritual (session-summary + commit-message + commit + push) in the subagent, not the orchestrator. Moving it to the orchestrator inflates parent context ~10x per step and defeats the sub-agent-per-step architecture. Harden the subagent's contract: "returning without committing is a `Failure:`", so the model can't plausibly skip it. (2026-05-30)
- Exactly one commit per autonomous-mode dispatch: no follow-ups, no fixups, no amends, no `--no-verify`. Generalizes beyond autonomous mode: only commit when you're finally done and ready and proud of it. Discovered when a real /goal run made a scaffold commit (with summary) plus a follow-up test fix commit (no summary) and the latter tripped a one-summary-per-commit pre-commit hook. (2026-05-30)
- `commit-msg.md` is gitignored AND persists between commits; it doesn't auto-clear. ALWAYS regenerate via the commit-message procedure before each commit; a stale message from a prior commit will silently ride along otherwise. ## Python

- Resolve a caller-supplied path once at the argv boundary when several consumers read it: `review-server.py` resolves the feedback path right after `parse_argv` so the file write, the Saved page's rendered path, the injected download filename, and the startup line all report one absolute path. The plan said "show the resolved path" but the resolve was lazy, so the Saved page rendered the relative argv path while the file landed at the absolute one; the validator flagged it as a warn and it cost a fix round (Section 5 Step 5, iter 1). Resolve-to-absolute at the input boundary, not at each use. (2026-11-09)
- `socket.gaierror` subclasses `OSError`, so a bind-port countdown loop that catches `OSError` to mean "this port is in use" also swallows an unresolvable host: an invalid `--bind` address burns every attempt and reports "No free port" instead of the real name-resolution failure. When a plan step says "catch OSError on a bind attempt," remember the address can fail the same way the port can; resolve or pre-validate the bind address before the port loop so a bad host surfaces as itself. (2026-11-09)
- A `finally`-based cleanup guard is unreachable on SIGTERM in Python: the interpreter exits without unwinding the stack, so the `finally` never runs unless a handler converts the signal into a normal exit. The review server's self-owned-unlink guard sat in a `finally` on exactly the path `kill_existing_server` SIGTERMs a predecessor, so without a handler it never ran and both servers' state files leaked; `signal.signal(signal.SIGTERM, lambda *_: shutdown_event.set())` made the wait return and the `finally` run. Any plan step that puts cleanup in `finally` for a process that gets SIGTERMed must also plan the handler. (2026-11-09)
